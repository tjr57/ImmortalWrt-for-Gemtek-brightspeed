# NPU 固定地址观察模块

本工具用于核对 AP23 NPU 固件的 CPU 接收队列地址换算。它是临时诊断工具，
不是 TXFREE 截断修复，也没有被选入生产固件或自动启动。

生产文件 `src/xr_npu_addresses.c` 通过 `dev_get_regmap()` 使用已绑定驱动的映射，
不依赖私有驱动结构，不创建新的物理内存映射。只允许 XR1710G / EN7581、
`airoha-npu` 驱动和精确的 `1e900000 + 313000` 资源范围。
设备正在探测或移除时，`device_trylock()` 立即拒绝读取。

唯一端点是只允许 root 读取的
`/sys/kernel/debug/xr_npu_addresses/snapshot`，另要求 `CAP_SYS_RAWIO`。
模块没有可配置地址、寄存器写入、帧内容读取、token ID 读取或自动加载项。
端点两次顺序读取 14 个固定字段，明确标记 `atomic=0`，不将它声称为原子快照。
固件源码和 AP23 的 NPU blob SHA256 必须为
`e743d1b59a9ca6d043e38ff71075e8d28702a104b94abb17a4035514efda4643`。
SRAM 字段含义来自该二进制的逐指令分析，不能用于任意其他版本。

## 已完成验证

- 独立 Linux 6.18.54 客体开启 KASAN / lockdep，12 项检查通过。
  检查正常、变化、缺设备、错误板型/芯片/资源、缺 regmap、读取失败、设备锁被占用、
  驱动解绑和卸载；正常路径还检查权限、重复读取和打开文件时禁止卸载。
  regmap 仿真总线验证零写入、没有越过固定字段，错误身份在任何读取之前拒绝。
- 原有实验内核缺少 regmap，因此单独复制并构建内核，未修改旧的资格验证内核。
  本次 `/dev/kvm` 不存在，首次 KVM 启动失败留档，最终使用 QEMU TCG 运行真实客体内核。
  OF 身份由虚拟设备属性替代，设备由测试驱动和 regmap 仿真总线提供。
- ARM 模块按 AP23 内核源码、配置、符号表编译，`make -j12`，vermagic 与已打包 mt76 一致。
  VM 身份适配不包含在 ARM 二进制中，生产配置、符号表和无线模块保持不变。
- AP1 的 NPU 关闭状态下，一次临时加载/读取/卸载通过。14 个字段均为零。
  两台 AP 同一启动实例和配置，服务正常；模块和临时文件已删除。
  该结果仅证明端点可读，不证明运行中队列地址或 NPU 物理总线映射。

## 接续要求

1. 将本端点加入首故障采集，必须独立限时、限量；单个端点阻塞不能阻塞另一个端点或恢复。
2. 给新诊断启动加入一次性的模块加载，并验证缺模块/加载失败时不能进行无证据的 NPU 实验。
3. 对变更的故障采集和一次性启动路径完成相应真实客体测试，再创建新的 epoch 3。
   不得复跑已完成的 epoch 1 / 2 或此基线脚本。
4. AP1 运行时取得 CPU RX DMA 基址和 NPU 缓存别名；AP2 保持 NPU 关闭。
   不通过启用实验功能来替代根因证明。

虚拟机不能证明 AN7581 总线访问、缓存一致性、射频、硬件死锁恢复或突然断电持久性。
仍未取得异常发生前的原始 Wi-Fi 描述符长度/LAST；两个取证缺口均需明确保留。
